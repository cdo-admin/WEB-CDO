## 1. Ringkasan Eksekutif
Commit e73bb76 melakukan apa yang diklaim pesan commit-nya. Halaman Galeri tidak lagi error (`ReferenceError`). Semua temuan lint frontend hilang (sebelumnya 59 peringatan, sekarang 0). Build tetap berhasil, dan bundle utama turun dari 583,7 kB ke 332,3 kB. Tidak ada import yang putus dan tidak ada import melingkar. Perubahan perilaku di PhoneInput, OrderBuilder, AdminApp, Dashboard dan CmsProvider terbukti setara dengan versi sebelumnya. Satu perubahan perilaku kecil ada di Header: laci menu HP sekarang hilang seketika saat pindah halaman, tanpa animasi geser keluar.

Ada dua masalah proses dan dua risiko kecil. Masalah prosesnya: commit dikirim langsung ke `main` tanpa PR, terlalu besar dan berisi banyak urusan sekaligus, dan tidak disertai tes sama sekali. Dua risiko kecilnya: animasi laci di Header, dan foto portofolio yang diganti di kode tetapi tidak di data CMS atau database. Tidak ada temuan Critical atau High. Verdict: **PASS WITH CONDITIONS**. Syaratnya ada di bagian 4 (AUD-001-F1 dan AUD-001-F2).

## 4. Temuan

### AUD-001-F1: Commit langsung ke `main`, format bukan Conventional Commits, ukuran dan cakupan melebihi kebijakan
| Field | Nilai |
|---|---|
| Severity | Medium |
| Kategori | Quality (proses) |

**Deskripsi.** Commit ada di `main` dan `origin/main` dengan histori linear di atas `c8b2023`, tanpa merge commit atau PR. Judul commit tidak memakai format `type(scope): summary`. Satu commit menggabungkan bugfix, penggantian aset, refactor modul dan konfigurasi build, dengan 909 baris berubah.

**Dampak.** Tidak ada review sebelum masuk `main`. Satu commit sebesar ini sulit di-revert sebagian. Jika salah satu bagiannya bermasalah (misalnya konfigurasi chunk), semua bagian lain ikut ter-revert.

**Rekomendasi.** Untuk perubahan berikutnya, kerjakan di branch `fix/…` atau `refactor/…`, buka PR, dan pecah per urusan (bugfix Galeri, aset, refactor lint, konfigurasi build). Pakai format Conventional Commits. Baris co-author AI sudah ada dan sudah sesuai.

### AUD-001-F3: Laci menu HP hilang seketika saat pindah halaman (animasi geser keluar hilang)
| Field | Nilai |
|---|---|
| Severity | Low |
| Kategori | Quality (perubahan perilaku UI) |
| Lokasi | `frontend/src/components/Header.jsx:45-46` (dipicu juga oleh link laci di `:107` dan `:115`) |
| Status | Open |

**Deskripsi.** Dulu, perpindahan halaman memanggil `closeMenu()` dari effect. Laci bergeser keluar, lalu overlay disembunyikan 350 ms kemudian. Sekarang penyesuaian saat render langsung memanggil `setSlide(false); setMenu(false)`, sehingga overlay langsung mendapat kelas `hidden` tanpa animasi. Ini cara utama laci dipakai, karena setiap klik link di laci menuju halaman lain memicu perpindahan halaman. Kunci scroll body tetap benar. Perubahan ini justru memperbaiki kebocoran kunci scroll saat Header di-unmount.

**Bukti.**
```jsx
// Header.jsx:45-46
const [prevPage, setPrevPage] = useState(page);
if (page !== prevPage) { setPrevPage(page); if (menu) { setSlide(false); setMenu(false); } }
```
Probe jsdom (buka laci, lalu `navigate('/about')`, lalu periksa langsung dan setelah 400 ms):
```
HEADER BASE {"afterOpen":{"hidden":false,"overflow":"hidden"},"t0":{"hidden":false,"slideIn":false,"overflow":""},"t400":{"hidden":true,"overflow":""}}
HEADER NEW  {"afterOpen":{"hidden":false,"overflow":"hidden"},"t0":{"hidden":true,"slideIn":false,"overflow":""},"t400":{"hidden":true,"overflow":""}}
HEADER-UNMOUNT BASE "hidden"    # kunci scroll bocor setelah unmount (bug lama)
HEADER-UNMOUNT NEW  ""          # sudah diperbaiki
```

**Dampak.** Hanya kosmetik. Tidak ada state yang rusak. Bisa terlihat seperti "kedip" di HP.

**Rekomendasi.** Jika animasi dianggap penting, cukup reset `slide` saat render dan biarkan `menu` ditutup oleh timer 350 ms. Contoh: `if (menu) { setSlide(false); }` lalu `setTimeout(() => setMenu(false), 350)` dari effect atau handler. Jika perilaku baru diterima, catat sebagai keputusan sadar.

**Referensi.** React docs, "Adjusting some state when a prop changes".

### AUD-001-F4: Penggantian foto portofolio hanya di kode. Override CMS dan data portofolio di database tidak ikut
| Field | Nilai |
|---|---|
| Severity | Low |
| Kategori | Quality (konsistensi data) |
| Lokasi | `frontend/src/pages/PortfolioPage.jsx:86`, `:152`. `frontend/src/admin/PortfolioAdmin.jsx:12` (`SEED_PF`). `frontend/src/cms/components.jsx:38-46` (`CImg`) |
| Status | Open (perlu dicek di data produksi) |

**Deskripsi.** `CImg` mencari override gambar CMS dengan kunci **src asli**: `pick('img', scope, src)`. Commit mengganti src dua kartu dari URL Unsplash ke file lokal. Jika admin sebelumnya sudah mengganti foto rusak itu lewat "Edit Website" atau "Galeri Gambar", override tersebut tersimpan dengan kunci URL Unsplash lama. Override itu sekarang tidak berlaku lagi dan menjadi baris yatim. Selain itu, `SEED_PF` hanya dipakai saat admin menekan "Impor 6 proyek bawaan". Proyek yang sudah pernah diimpor ke tabel item tetap menyimpan `image_url` Unsplash yang mati jika mode "atur dari admin" aktif.

**Bukti.**
```jsx
// components.jsx:38-46
export function CImg({ src, removeOnError, ...rest }) {
  const { pick } = useCms();
  const scope = useScope();
  const ov = pick('img', scope, src);          // kunci = src asli
  ...
  return <img {...props} src={assetUrl(useOv ? ov.id : src)} data-cms-orig-src={src} />;
}
// PortfolioPage.jsx:86 (sebelumnya "https://images.unsplash.com/photo-1504917599217-...")
<CImg src={"assets/images/produk dan layanan/gambar welding.jpg"} ... />
// PortfolioAdmin.jsx:134: SEED_PF hanya dipakai di tombol impor
onClick={() => importMany(SEED_PF.map(...), '6 proyek diimpor')}
```
File tujuan ada dengan huruf besar/kecil yang tepat:
```
$ git ls-tree -r --name-only e73bb76 | grep -iE "gambar welding|purging pipeline layanan"
frontend/public/assets/images/produk dan layanan/gambar welding.jpg
frontend/public/assets/images/produk dan layanan/purging pipeline layanan.jpg
```

**Dampak.** Di lingkungan yang sudah punya data, foto pilihan admin bisa hilang dan diganti foto bawaan baru, atau foto mati tetap muncul di mode portofolio terkelola. Auditor tidak bisa memastikan kondisi ini terjadi karena isi database tidak diakses.

**Rekomendasi.** Cek tabel `site-content` (kind `img`, key = dua URL Unsplash lama) dan tabel item portofolio. Jika ada baris yang terdampak, pindahkan kuncinya ke path baru atau perbarui `image_url` lewat panel admin atau migrasi data.

**Referensi.** —

## 5. Observasi (bukan temuan)
- **Fast refresh di file halaman.** `.oxlintrc.json:6` menambahkan `allowExportNames: ["meta"]`. Aturan lint jadi lolos, tetapi `export const meta` di `src/pages/*.jsx` tetap menjadi export non-komponen. Berdasarkan cara kerja refresh boundary @vitejs/plugin-react, edit file halaman kemungkinan masih memicu full reload, jadi klaim "agar fast refresh berjalan" hanya berlaku untuk modul yang dipindahkan. Ini belum diverifikasi saat runtime dan hanya berdampak ke pengalaman developer. Tanpa whitelist itu, ada 8 peringatan `only-export-components` di `src/pages/*.jsx:4-8`.
- **OrderBuilder** (`OrderBuilder.jsx:45`). setState saat render konvergen dalam satu render tambahan, karena `opt` selalu diambil dari `qc.options`. Probe dengan produk default disembunyikan admin menghasilkan `{"selected":"Oksigen Industri","consoleErrors":0}` di kedua commit. Tidak ada loop render.
- **AdminApp** (`AdminApp.jsx:62-63`). Tab awal sekarang langsung terpasang pada render pertama (dulu baru setelah effect). Tidak ada regresi. Hash tab yang tidak valid tetap menampilkan konten kosong, sama seperti sebelumnya (bug lama).
- **Dashboard** (`Dashboard.jsx:66,69`). `setD(null)` dipindah ke handler. `load` hanya berubah jika `days` berubah, karena `fail` stabil (`toast` di `common.jsx:8` memakai `useCallback([])`). Perilakunya setara. Race antara respons lama dan baru saat `days` diganti cepat adalah bug lama, bukan dari commit ini.
- **CmsProvider/EditBridge** (`CmsProvider.jsx:66`). `st.current` hanya dibaca di event handler (click, message) yang terpasang di passive effect, dan selalu setelah layout effect. Tidak ada pembacaan ref yang basi.
- **PhoneInput** (`PhoneInput.jsx:18,37`). `checkRef` diinisialisasi dengan `check` dari render pertama, jadi tidak pernah kosong. `validatePhones` dipanggil dari handler submit, setelah commit. `isoRef` juga ditulis langsung di handler (`:32`, `:60`). Probe memberi hasil identik di kedua commit: `{"r1":[true,"+62 812 3456 7890"],"r2":[true,"+65 9123 4567"],"r3":[false,"12345","SG"]}`.
- **Timer tertunda di Header.** `closeMenu` menjadwalkan `setMenu(false)` 350 ms. Jika laci dibuka lagi dalam rentang itu, laci tertutup sendiri. Ini bug lama yang sudah ada di c8b2023, bukan dari commit ini.
- **Konfigurasi chunk** (`vite.config.js:10-19`). Regex hanya menangkap paket tepat bernama `react`, `react-dom`, `scheduler`, `react-router`, `react-router-dom`, `cookie` dan `set-cookie-parser` (dua yang terakhir dependency langsung react-router 7.18.7). React hanya ada di `vendor-react` (string `19.3.1` muncul 2 kali di vendor dan 0 kali di chunk lain). `index.html` mem-preload chunk vendor. Mode `laravel` tetap memakai `outDir` `../backend/public/app` dan base `/app/`. Total JS awal naik sedikit (583,7 → 589,6 kB, overhead runtime chunk), tetapi chunk React sekarang bisa di-cache terpisah.
- **Keamanan (ringan).** Tidak ada dependency baru. `package.json` tidak berubah. Tidak ada rahasia. Tidak ada input atau endpoint baru. Filter `javascript:` di `CImg` dan `CLink` serta pemeriksaan origin `postMessage` tidak berubah. Tidak ada temuan keamanan.

## 6. Praktik Baik yang Dicatat
- Klaim commit terverifikasi: lint 59 → 0 peringatan, ReferenceError Galeri hilang, nama file AR/CO2 sesuai kode, dan bundle utama di bawah 500 kB.
- Pemindahan modul rapi: 316 named import valid, 0 siklus import, dan modul `.js` baru berisi kode yang dipindah apa adanya (diff menunjukkan isi identik).
- Kunci scroll body di Header sekarang dilepas lewat cleanup effect, sehingga kebocoran saat unmount yang ada di c8b2023 ikut diperbaiki.
- Pesan commit menjelaskan alasan setiap perubahan dan mencantumkan atribusi co-author AI.

## 7. Keterbatasan
- Probe perilaku berjalan di jsdom dengan `fetch` di-stub (offline). Ini bukan browser sungguhan: animasi CSS, layout dan Safari/HP tidak diuji.
- Isi database produksi dan staging (override CMS, item portofolio) tidak diakses. AUD-001-F4 bersifat kondisional.
- Apakah dua URL Unsplash itu benar-benar 404 tidak diverifikasi lewat jaringan. Audit hanya memastikan file pengganti ada.
- Proteksi branch di remote dan histori PR tidak diperiksa lewat API GitHub. Kesimpulan "tanpa PR" berdasarkan histori linear dan tidak adanya merge commit.
- Probe memakai `node_modules` bersama (lewat junction) yang sudah berisi vitest, jsdom dan @testing-library hasil instalasi agent lain. Auditor tidak menginstal paket apa pun.
- Backend Laravel tidak diaudit.
